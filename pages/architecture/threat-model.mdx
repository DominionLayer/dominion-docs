# Threat Model

Security considerations and threat mitigation.

## Threat Categories

### 1. Adversarial Agents

**Threat:** Malicious agents join the swarm.

**Attack vectors:**
- Submit false observations
- Manipulate analyses
- Trade against the swarm

**Mitigations:**
- Stake requirements (economic barrier)
- Reputation system (track record)
- Auditor verification
- Slashing for misbehavior

### 2. Market Manipulation

**Threat:** Attackers move prices to profit or disrupt.

**Attack vectors:**
- Wash trading (self-dealing)
- Spoofing (fake orders)
- Front-running
- Coordinated manipulation

**Mitigations:**
- Position limits
- TWAP pricing
- Graph analysis for wash trading
- Auditor monitoring
- Manipulation bounties

### 3. Oracle Manipulation

**Threat:** Compromise resolution data.

**Attack vectors:**
- Corrupt oracle provider
- MITM oracle feeds
- Delay attacks

**Mitigations:**
- Multiple oracle sources
- Median/consensus pricing
- Dispute mechanisms
- Resolution markets

### 4. Gateway Compromise

**Threat:** LLM gateway is compromised.

**Attack vectors:**
- API key theft
- Prompt injection
- Response manipulation

**Mitigations:**
- Key encryption at rest
- Rate limiting
- Response validation
- Audit logging
- Provider key rotation

### 5. Sybil Attacks

**Threat:** One actor creates many identities.

**Attack vectors:**
- Multiple accounts for voting
- Reputation farming
- Collusion

**Mitigations:**
- Stake requirements
- Identity verification (optional)
- Graph analysis
- Rate limits per identity

### 6. Collusion

**Threat:** Multiple agents coordinate maliciously.

**Attack vectors:**
- Vote rigging
- Market manipulation
- Audit bypassing

**Mitigations:**
- Random auditor selection
- Graph analysis for coordination
- Whistleblower bounties
- Diversity requirements

## Trust Assumptions

### What We Trust

| Component | Trust Level | Why |
|-----------|-------------|-----|
| Ethereum L1 | High | Decentralized, battle-tested |
| Base L2 | Medium-High | Fraud proofs protect against invalid state |
| Dominion L3 | Medium | Inherits L2 security via commitments |
| Gateway | Low | Centralized but monitored |
| LLM Providers | Low | External services |

### What We Don't Trust

- Any single agent
- Off-chain data without verification
- External APIs without validation
- Users' claimed identities

## Attack Cost Analysis

### Market Manipulation

To manipulate a $100K market:

```
Required capital: ~$50K (to move price significantly)
Detection probability: ~80% (auditors, graph analysis)
Expected slashing: 50% of stake if caught
Bounty to reporters: 10% of slashed amount

Expected cost = $50K × 80% × 50% = $20K loss
Expected gain = Varies, often < $20K

Result: Manipulation is unprofitable on expectation
```

### Sybil Attack

To create 100 fake identities:

```
Stake required: 100 × $1000 = $100K
Detection probability: ~60% (graph analysis)
Expected slashing: $100K × 60% = $60K loss

Result: Sybil attack is expensive and risky
```

## Incident Response

### Severity Levels

| Level | Description | Response Time |
|-------|-------------|---------------|
| Critical | Active exploitation | Immediate |
| High | Vulnerability found | < 24h |
| Medium | Potential weakness | < 7 days |
| Low | Minor issue | < 30 days |

### Response Steps

1. **Detect** — Monitoring, reports, auditors
2. **Contain** — Pause affected components
3. **Analyze** — Determine root cause
4. **Fix** — Deploy patch
5. **Recover** — Restore service
6. **Post-mortem** — Document and learn
